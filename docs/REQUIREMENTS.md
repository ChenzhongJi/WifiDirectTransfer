## 实现备注

- W3：接收文件拖出使用 `FileDrop` 加内部标记；在应用窗口内松手不会加入发送队列，只有从资源管理器拖入的外部文件才会入队。
- UI：主窗口为 Windows 11 工具型布局：顶部连接/能力状态栏，左侧连接方式、设备与文本操作，右侧“发送 / 接收”标签工作区，底部状态栏。发送队列按顶层项目显示：直接文件一行、文件夹一行，文件夹行显示文件数、总大小、汇总状态和汇总进度，不展开内部文件；文件夹支持整组上移、下移和移除。接收列表同样按顶层项目显示：直接文件一行、文件夹一行，文件夹行显示文件数、空文件夹数、总大小、最近接收时间和接收状态，支持打开和拖出文件夹。可折叠“详情”面板显示项目大小、已发送、速率、ETA、续传偏移和队列位置；“更多设置”折叠剪贴板、远程文本、同名文件策略、接收目录和测试文件。日志位于工作区下方并可折叠。标签头显示发送/接收活动状态。接收标签包含“正在接收”进度和本次接收项目列表，支持拖出；选中接收项目可打开所在文件夹，文件/文件夹被外部删除时给出提示。文本消息显示完整日期，正文可选择复制。文件夹拖入保留根目录名和子目录结构；1.3+ 对端之间保留空文件夹。顶部连接状态旁提供“断开”按钮，有未完成传输或等待发送的文件时先确认。
- UI 对话框：关于、传输历史、文本消息、发送文本、未完成传输、接收确认、剪贴板/远程文本开启确认和后台关闭确认统一使用共享对话框标题、正文、卡片、警告卡、输入框、主/次/危险按钮样式；传输历史表头与行、文本消息卡片、未完成传输列表同步使用新主题。仅改 XAML 与样式，不改确认流程和键盘行为。
- 主题（1.1.1）：`Themes/Light.xaml` / `Themes/Dark.xaml` 提供颜色和画刷，`WdtTheme.xaml` 保持样式并使用 `DynamicResource`；`ThemeManager` 支持跟随系统、浅色、深色，切换时替换合并字典并同步 DWM 原生标题栏。设置持久化在 `settings.json` 的 `ThemeMode`。高对比度暂回退浅色。
- 传输性能：每个 64 KiB 块的 Ack 不再写入 UI 日志；发送/接收进度最多每 150 ms 刷新一次，最终 100% 必达；UI 日志最多保留 2000 行（文件日志仍完整保留）。
- T6：队列运行期间可以继续“添加文件”或拖入，追加的文件在当前文件完成后按顺序继续发送；仍然是同一方向串行，双向可各自并行。“清空”在运行期间仍禁用。1.3 起队列按顶层项目分组，文件夹组内文件保持连续，整组上移/下移/移除。
- W4：显式文本传输。接收端需开启“允许接收远程文本”（默认关闭，首次确认）；文本只保存在内存收件箱中，最多 100 条，可单条复制或清空；未开启时回 `TextRejected`。单条上限 64 KiB，不写历史、不落盘。协议版本为 v4。
- 设置/诊断：接收目录可在主界面更改并持久化到 `settings.json`；导出诊断会打包日志、设置和构建信息到 `%LOCALAPPDATA%\WifiDirectTransfer\diagnostics\*.zip`；“关于”显示本端构建、协议版本、对端构建和运行环境。应用与托盘图标使用 `Assets/app.ico`。
- R4/R5/R6：自动化覆盖 1/64 KiB 边界的单块与多块文件、300 个 1 KiB 小文件队列、零字节、路径穿越、Windows 保留名、非法字符、Unicode 名、150 字符长名、目标目录不可创建、最终改名被目录阻塞、16 GiB+1 超限拒绝。接收端在开始接收或写块失败时会尽力回发 `TransferError`，让发送端立即得到具体原因，而不是等 30 秒 ACK 超时。3 GiB / 16 GiB 实传仍需双机手动验证。
- U4：发送/接收的完成、失败、跳过记录持久化到 `%LOCALAPPDATA%\WifiDirectTransfer\history.json`，最多保留 1000 条；主窗口“传输历史”可查看、打开所在文件夹、清空。写入失败只记录日志，不影响传输。
- 协议握手：连接建立后双方先交换 `Hello`（协议版本、单帧上限、构建号）。版本不一致或对端 10 秒内没有响应（旧构建）时明确提示并断开，不再进入传输。日志会记录对端构建号。
- C2 发现重试：发送端一次“扫描设备”在约 15 秒内自动重试；连续 3 次空结果后重启 PeerFinder。未发现设备时提示确认对端已点击“等待连接”并保持前台。
- C2 接收端广播恢复：等待中按钮显示“重新等待”，点击后停止并重启 PeerFinder。监听 `WM_POWERBROADCAST`、WTS 锁屏/解锁和 `NetworkAddressChanged`，在休眠恢复、解锁、网络变化且没有活动连接时重启等待广播；连接请求被拒绝/超时或连接断开后也自动重启。等待中且无连接/传输时每 2 分钟刷新一次广播；PeerFinder 启停后 5 秒内忽略网络变化事件，避免自身触发恢复循环。连接、扫描、接收确认或传输进行中忽略网络变化，避免 Wi-Fi Direct 虚拟网卡变化取消正在进行的 `ConnectAsync`。手动断开或远端断开后立即恢复本端发现：接收端重启等待广播，发送端重启发现；连接超时提示指导用户在对端点“重新等待”。协议不变。
- 文件夹层级（1.1）：协议 v4、文件头 v2；`FileStart` payload 增加 UTF-8 相对目录，接收端用 `SafeRelativePath` 校验并创建子目录。1.0.x 对端不再兼容。
- 空文件夹（1.3）：新增 `DirectoryManifest` 控制消息（1.3+ 可选扩展，协议号仍为 v4）。发送端在文件前发送空文件夹清单，接收端用 `SafeRelativePath` 校验并创建目录；单次连接最多 100,000 个条目。1.2.x 对端不发送该消息，文件传输继续互通，但空文件夹跳过并提示。队列支持只有空文件夹的计划、运行中追加和自动重连补发。队列按顶层项目（文件或文件夹）显示，文件夹组支持整组上移、下移和移除；同一队列内重复顶层文件夹在入队时自动改写为 `docs (2)` 等目标路径。接收列表按实际落盘路径的顶层项目分组，文件夹行汇总文件数、空文件夹数、总大小、最近接收时间和接收状态；空文件夹清单会归入对应文件夹项目。
- 队列控制（1.1）：`TransferQueueManager` 支持当前块完成后暂停/继续、等待文件上移/下移和移除；已完成/失败/跳过文件可从队列移除。详情面板跟随选中的队列文件，未选择时回退到当前文件。右键会先选中目标文件；移动仅对等待文件可用。
- 自动重连（1.1）：发送端在队列运行中意外断开时最多尝试 3 次重连；成功后重新入队未完成文件并续传。手动断开设置 `_suppressAutoReconnect`，不触发自动重连。接收端继续使用等待广播恢复。
- 通知（1.1）：连接请求、传输完成/失败、自动重连结果通过托盘气泡通知；点击通知恢复窗口。`ReceiverPreferences.NotificationsEnabled` 持久化通知开关。
- R2/U7：启动时扫描接收目录的 `.part` / `.meta`，发现未完成传输时提示“保留（等待续传）”或“删除这些文件”；保留后对端再次发送同名文件会自动续传。托盘图标常驻，双击或菜单可恢复窗口。关闭窗口时若存在连接、等待中的接收端或运行中的队列，弹出“后台继续 / 取消传输并退出 / 返回”；后台继续只隐藏窗口，连接和传输不中断。系统注销/关机时直接退出，不弹确认。应用为单实例，重复启动会激活已有窗口，避免两个进程同时占用 PeerFinder 和托盘图标。
- S4：`app.manifest` 使用 `asInvoker`，声明 `PerMonitorV2` DPI 感知和 `longPathAware`，不请求管理员权限。
- T5：接收端在 SHA-256 校验通过且正式文件落盘后发送 `FileVerified`（携带接收端计算的摘要）；发送端收到匹配摘要后才把文件标记为完成，队列随后处理下一个文件。校验失败或落盘失败时接收端发送 `TransferError`，不再让发送端空等。
- W1：数 MB 以上的剪贴板图片可能不会出现在 Windows 剪贴板历史（Win+V）中，但仍保留在当前剪贴板里，直接 Ctrl+V 粘贴正常。同步是否成功应以接收端状态栏和日志为准，不能以 Win+V 是否显示判断。
- 大文件（1.2）：应用层单文件上限为 16 GiB，`FileSize` 和所有进度/队列统计保持 64 位；协议 v4、文件头 v2 不变。1.2 与 1.1.x 在 2 GiB 以内互通，超过 2 GiB 要求两端都是 1.2+；连接后按握手构建号自动把对端为 1.1.x 时的发送上限限制为 2 GiB。接收端磁盘空间预检使用队列总字节和单文件字节的 64 位较大值。
- 速率/ETA（1.2）：`TransferRateTracker` 用指数滑动平均计算速率，发送队列、当前发送文件、总体进度和接收面板显示速率与预计剩余时间；采样间隔 200 ms，UI 进度仍按 150 ms 节流。
- Windows 集成（1.2）：`--send` 启动参数支持文件和文件夹路径；第二个实例通过当前用户命名管道把路径传给已有窗口。资源管理器右键菜单只写 `HKCU\Software\Classes\*\shell`、`Directory\shell` 和 `Directory\Background\shell`，由“更多设置”开关控制。Windows 系统共享目标需要 MSIX 包身份，1.2/1.3 暂不实现。
- 历史/诊断（1.3.1）：完成的发送和接收记录保存耗时与平均速率，历史窗口显示平均速度和耗时；诊断信息包含当前传输速率、对端单文件上限、空文件夹清单支持、发送队列项目/文件/空文件夹数量和本次接收项目/文件数量。
- 高对比度（1.3.1）：`Themes/HighContrast.xaml` 合并 Light 主题并覆盖关键画刷为 `SystemColors`；高对比度开启时优先使用系统高对比度颜色，关闭后恢复跟随系统/浅色/深色主题。主窗口最小宽度 1000，详情面板宽度 220。
- 设备身份（1.4）：每台设备在 Windows 用户密钥存储（CNG）中生成 ECDSA P-256 私钥，私钥不可导出。连接握手后交换 `IdentityHello`（nonce、公钥、设备名）和 `IdentityProof`（对端 nonce 签名），双方验证私钥持有后由两个 nonce 和两个公钥派生同一个 6 位配对码；随后交换 `IdentityTrust` 本地信任状态，任一端未信任时两端都显示配对码。身份交换是可选的 `ControlMessage` 扩展，构建号 1.4+ 才启用；1.3 及更早对端不发送身份消息，回退到原有接收确认。
- 可信设备（1.4）：信任关系以公钥 SHA-256 指纹为唯一键，保存公钥、设备名、最近 Peer Id/名称和时间到 `%LOCALAPPDATA%\WifiDirectTransfer\trusted-devices.json`。首次配对不自动接受，两端必须确认配对码一致；用户可选择信任。可信设备自动接受默认开启，可在“更多设置”关闭；连接前按 Peer Id 或唯一显示名称预判，身份交换后必须指纹匹配，名称相同但公钥变化会被拒绝并断开。升级到 1.4 前的历史设备默认不受信任，需要重新配对。可信设备管理窗口支持查看和取消信任。
- 安全审计（1.4）：`%LOCALAPPDATA%\WifiDirectTransfer\audit.jsonl` 记录连接接受/拒绝/超时、身份验证成功/失败、配对接受/拒绝/超时、添加/移除可信设备、可信设备自动接受以及剪贴板和远程文本开关。日志使用 JSON Lines，按 1 MiB 轮转并保留 3 个文件，包含在诊断导出中；不记录文件内容、剪贴板内容或文本正文。
- 拒绝清理（1.4）：接收端在用户拒绝或接收确认超时后，会完成 PeerFinder 传输握手并立即关闭 socket，但不创建文件接收器、不进入身份或配对流程；随后保持等待广播，不重启 PeerFinder。只有 `AcceptAsync` 之后的失败才重启广播，避免未完成的连接请求残留导致后续 `ConnectionRequested` 不再触发。发送端连接失败后会清除本次使用的 `PeerInformation` 缓存，下次重试重新发现对端。
- 主题化对话框（1.4.1）：新增 `MessageDialogWindow`，替换 AboutWindow、HistoryWindow、TextInboxWindow 和 MainWindow 中全部原生 `MessageBox`。支持信息、警告、错误三种样式和确定、是/否两种按钮组合，`Enter` 触发默认按钮、`Esc` 取消，使用动态主题资源适配深色、浅色和高对比度。
- 窗口传输（1.5）：两端构建号均为 1.5+ 时，发送端在每个文件开始后发送 `WindowModeStart`（窗口 16 块、每 4 块累计 ACK），不再逐块等待 ACK；窗口满时才等待累计 ACK。接收端在窗口模式下每 4 块 Flush `.part` 并发送一次累计 ACK，旧发送端仍逐块 Flush + ACK。断点续传继续使用 `.meta` 的持久化偏移。1.4 及更早对端自动回退到逐块停等模式，协议版本仍为 v4，文件头仍为 v2。发送端遇到 `PeerFinder.ConnectAsync` 返回 E_INVALIDARG（过期 `PeerInformation`）时，自动清除缓存、重新发现并重试一次；重试失败按对端信息过期处理。普通连接首次尝试 20 秒，失败后重启发送端发现并等待 2 秒，再试 15 秒；仍失败则等待 3 秒、重新扫描后再试 15 秒，整体上限 60 秒。接收端正常连接结束后若 PeerFinder 仍处于 Listening，不再立即重启广播；显式“重新等待”时 Stop/Start 之间增加 800ms 释放延迟，Start 后等待 700ms 稳定。接收端在当前请求处理期间收到新请求时保留最新请求，当前请求结束后自动继续处理；`AcceptAsync` 超时缩短为 12 秒。
- 安装与自动更新（1.6）：提供 Inno Setup 安装包，按用户安装到 `%LOCALAPPDATA%\Programs\WifiDirectTransfer`，使用固定 AppId 支持覆盖升级，不需要管理员权限；卸载时可选择是否删除 `%LOCALAPPDATA%\WifiDirectTransfer` 数据，默认保留。安装版启动 20 秒后检查 `releases/latest/download/latest.json`（整体超时 20 秒），只接受 HTTPS + GitHub 域名，本地测试可用 `WDT_UPDATE_FEED` 指向 `file://` 清单；发现新版本后提示下载，校验大小和 SHA-256，再以 `/SILENT /SUPPRESSMSGBOXES /NORESTART` 启动安装器并退出，安装结束后由 Inno `[Run]` 重新启动应用。支持“跳过此版本”和关闭启动检查，设置持久化在 `settings.json` 的 `AutoUpdateCheckEnabled` 与 `SkippedUpdateVersion`；便携版不自我更新，只提供下载页入口。安装包暂未代码签名，首次运行会触发 SmartScreen 提示。
- 开机自启（1.6.2）：安装版可在“更多设置”启用，默认关闭。写入 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 的 `WifiDirectTransfer` 值，命令行为 `"<安装目录>\WifiDirectTransfer.App.exe" --tray`；注册表值是唯一事实来源，不写入 settings.json。带 `--tray` 启动时窗口最小化并隐藏到托盘，**不调用 `PeerFinder.Start`、不广播、不扫描、不自动等待连接**；用户打开窗口点击“等待连接”后才进入接收状态。便携版选项禁用；卸载时由安装器删除该 Run 项，不删除用户数据。 “关于”窗口和托盘提示显示版本号与构建提交短号。
