# Wi-Fi Direct 文件传输

[![CI](https://github.com/ChenzhongJi/WifiDirectTransfer/actions/workflows/ci.yml/badge.svg?branch=main)](https://github.com/ChenzhongJi/WifiDirectTransfer/actions/workflows/ci.yml)
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)

Windows 与 Windows 之间通过 Wi-Fi Direct 直连传输文件、文本和剪贴板内容的桌面工具。不需要互联网，不经过云端，连接建立后双方都可以发送和接收。

## 系统要求

- Windows 10 版本 1809（Build 17763）或更高，Windows 11 亦可。
- x64 系统。
- 无线网卡和驱动支持 Wi-Fi Direct 发现（`PeerFinder` 的 Browse 能力）。
- 推荐两端使用**同一构建**。1.1 起协议版本为 v4，不再兼容 1.0.x，旧构建会在握手阶段被明确拒绝。1.2 / 1.3 / 1.4 / 1.5 与 1.1.x 在 2 GiB 以内互通；超过 2 GiB 需要两端都使用 1.2 或更高版本。空文件夹需要两端都使用 1.3 或更高版本；可信设备身份验证需要两端都使用 1.4 或更高版本，旧对端会回退到手动接收确认。窗口传输需要两端都使用 1.5 或更高版本。连接后会按对端构建号自动限制发送上限、空文件夹和窗口传输能力。
- 发布包为自包含单文件，不需要单独安装 .NET 运行时。

如果启动后右上角提示“当前无线网卡或驱动不支持 Wi-Fi Direct 发现”，说明当前网卡/驱动不满足发现条件，应用不会继续调用发现接口。请更新无线网卡驱动或更换支持的设备。

## 快速开始

1. 在两台 Windows 电脑上分别解压发布包，运行 `WifiDirectTransfer.App.exe`。
2. 接收端选择“等待连接”，点击“等待连接”，保持窗口打开。等待中按钮会变为“重新等待”，如果发送端扫描不到，可以点击它立即重启接收端广播。
3. 发送端选择“连接设备”，点击“扫描设备”，选中对端，点击“连接选中设备”。
4. 接收端在 15 秒内点击“接受”。超时会自动拒绝。两端都是 1.4+ 时，首次连接还会显示 6 位配对码；确认两台电脑的配对码一致后接受，可选择“信任此设备”。已信任设备在“可信设备自动接受连接”开启时可跳过接收确认，但仍会验证公钥指纹。
5. 连接成功后，双方都可以发送文件：
   - 把文件或文件夹拖入窗口，或点击“添加文件…” / “添加文件夹…”。
   - 点击“开始传输”。
   - 传输期间仍可继续添加文件，新文件会在当前文件完成后按顺序发送。
   - 文件夹会保留根目录名和子目录结构；两端都是 1.3+ 时会保留空文件夹，旧对端会跳过空文件夹并提示。
   - 也可以在资源管理器中右键文件或文件夹，选择“通过 Wi-Fi Direct 发送”。首次使用需在“更多设置”中启用；应用未运行时会自动打开，已运行时会把路径交给现有窗口。Windows 11 可能需要在右键菜单中先选择“显示更多选项”。
6. 接收端在“接收”标签查看当前接收进度和本次接收项目。接收完成后可直接拖到资源管理器。
   - 接收列表按顶层项目显示：直接文件一行，文件夹一行；文件夹行显示文件数、空文件夹数、总大小和最近接收时间。
   - 选中文件或文件夹后可点击“打开所在文件夹”；双击也可以打开。
   - 如果文件或文件夹被外部移动或删除，列表会显示“文件已不存在”或“文件夹已不存在”，拖出或打开时给出提示。
7. 发送文本：双方连接后，点击左侧“发送文本”。接收端需要先在“更多设置”中开启“允许接收远程文本”。
   - 文本消息显示完整日期和时间。
   - 消息正文可以直接用鼠标选择，`Ctrl+C` 或右键复制；也可点击卡片右上角“复制”复制整条。
8. 剪贴板同步：在“更多设置”中开启。默认关闭，首次开启需要确认。
9. 需要结束连接时，点击顶部连接状态旁的“断开”。如果发送队列或传输仍在进行，会先确认再中断。

接收目录、同名文件策略、主题、剪贴板同步、远程文本、系统通知、可信设备自动接受和资源管理器右键菜单开关都在左侧“更多设置”中。接收目录的修改会在下次连接前生效。“管理可信设备…”可查看指纹并取消信任。

## 功能

- Wi-Fi Direct 设备发现、显式角色选择和连接建立。
- 双向文件传输，单方向串行队列，双向可并行。
- 文件夹传输保留根目录名和子目录结构；1.3+ 对端之间保留空文件夹，只含空文件夹的目录也可以发送。
- 传输队列按顶层项目显示：文件夹一行、直接文件一行；文件夹行显示文件数、总大小、汇总状态和进度，支持整组上移、下移和移除。
- 接收列表按顶层项目显示：直接文件一行、文件夹一行；文件夹行显示文件数、空文件夹数、总大小、最近接收时间和接收状态，支持打开和拖出文件夹。
- 发送端同一队列内重复顶层文件夹自动改用 `docs (2)` 等目标路径，接收端分开落盘和显示。
- 传输队列运行中追加文件；支持当前块完成后暂停/继续、上移/下移和移除文件；已完成文件也可从队列移除。
- 发送端在传输中意外断开时自动重连并续传，最多尝试 3 次；手动断开不触发。
- 系统通知：连接请求、传输完成/失败、自动重连结果；点击通知可恢复窗口。
- 深色模式：跟随系统 / 浅色 / 深色，切换立即生效，包含原生标题栏。
- 断点续传：接收端保留 `.part` / `.meta`，对端再次发送同名文件时继续。
- SHA-256 完整性校验，校验通过后才写入正式文件。
- 单文件最大 16 GiB。超过 2 GiB 的文件需要两端都使用 1.2 或更高版本。
- 发送队列、当前发送文件和接收面板显示实时速率与预计剩余时间；总体进度显示队列总速率。
- 资源管理器右键“通过 Wi-Fi Direct 发送”：只注册当前用户，支持文件和文件夹，应用已运行时复用现有窗口。
- 文本传输（W4）：接收端显式开启，单条最大 64 KiB，内存收件箱最多 100 条；显示完整日期，正文可选择复制。
- 剪贴板同步：文本和图片，默认关闭，带防循环处理。
- 同名文件策略：自动重命名、覆盖、跳过。
- 传输历史（含平均速度和耗时）、诊断导出、系统托盘、单实例。
- 主窗口“发送 / 接收”标签、队列表格、可折叠当前传输详情、可折叠日志。
- 接收文件拖出到资源管理器；在应用窗口内松手不会重新加入发送队列。
- 接收文件选中后可打开所在文件夹；文件被外部删除时会标记并提示。
- 顶部连接状态旁提供“断开”按钮；有未完成传输或等待发送的文件时先确认。
- 设备身份与可信设备（1.4）：ECDSA P-256 设备密钥保存在 Windows 用户密钥存储中，私钥不可导出；首次配对显示两端一致的 6 位配对码，信任关系以公钥 SHA-256 指纹为准。可信设备自动接受默认开启，可随时关闭或取消信任。
- 安全审计（1.4）：连接、身份验证、配对、信任变更和敏感功能开关写入本地 `audit.jsonl`，随诊断包导出，不记录文件内容、剪贴板内容或文本正文。
- 主题化对话框（1.4.1）：确认、提示和错误窗口统一使用应用主题，支持深色、浅色、高对比度、`Enter` 默认按钮和 `Esc` 取消。
- 窗口传输（1.5）：两端都是 1.5+ 时启用滑动窗口和累计 ACK，不再每 64 KiB 等待一次确认；旧对端自动回退到逐块停等模式。
- 性能调优（1.5.1）：窗口提升到 32 块（约 2 MiB），每 8 块发送一次累计 ACK；接收端 Flush 与 ACK 解耦，每 16 块（约 1 MiB）Flush 一次，文件结束时完整 Flush。大文件日志增加窗口实际等待、发送耗时、接收端写入/Flush/ACK 耗时统计。

## 界面说明

- 顶部：连接状态、对端名称、Wi-Fi Direct 能力状态。
- 左侧：连接方式、设备列表、文本操作、更多设置。
- 右侧：发送 / 接收标签、传输队列、当前传输详情。发送队列按顶层项目显示，文件夹不展开内部文件。
- 底部：日志和状态栏。
- “详情”按钮展开当前文件的大小、已发送字节、实时速率、预计剩余、续传偏移和队列位置。
- 日志可以折叠；传输历史、诊断、关于和清空日志都在日志栏。

## 安全与隐私

- 文件通过 Wi-Fi Direct 链路传输，链路层加密。
- 1.4+ 对端会交换 ECDSA P-256 设备身份，首次配对必须在两端确认相同的 6 位配对码；可信设备以公钥 SHA-256 指纹识别，显示名称相同但公钥变化会拒绝连接。
- 接收端必须确认接收请求，15 秒未操作自动拒绝。只有已信任且公钥指纹匹配的设备才可能自动接受；可在“更多设置”关闭可信设备自动接受。
- 安全审计日志记录连接、身份、配对、信任和敏感开关事件；不记录文件内容、剪贴板内容或文本正文。
- 发送端只有收到接收端 SHA-256 校验通过的确认后，才把文件标记为完成。
- 剪贴板同步和远程文本默认关闭，首次开启需要确认。
- 文本只保存在内存收件箱中，不自动打开、不写入历史、不落盘。
- 应用不依赖互联网，不上传文件或剪贴板内容。
- 剪贴板同步开启时，对端可以看到你复制的内容；敏感内容请先关闭同步。

## 已知限制

- 单文件上限 16 GiB；超过 2 GiB 需要两端都使用 1.2 或更高版本。
- 单条文本上限 64 KiB；收件箱最多 100 条，关闭应用后清空。
- 剪贴板图片上限 32 MiB。
- 文件夹会保留目录结构；空文件夹只有两端都是 1.3+ 时才会保留，旧对端会跳过并提示。
- 接收端已有同名顶层文件夹时默认合并；发送端同一队列内重复文件夹会自动使用 `docs (2)` 等路径区分，跨会话不处理已有目录冲突。
- 1.1 起协议版本为 v4，不兼容 1.0.x；1.2 / 1.3 / 1.4 / 1.5 与 1.1.x 在 2 GiB 以内互通，空文件夹需要 1.3+，设备身份验证需要两端 1.4+，窗口传输需要两端 1.5+。
- Windows 系统共享目标尚未实现：未打包的 WPF 应用缺少 MSIX 包身份，无法注册 ShareTarget。
- 资源管理器右键菜单是传统 Win32 菜单项；Windows 11 默认新菜单中可能位于“显示更多选项”下。
- 资源管理器多选时当前只发送第一个项目；需要发送多个文件时请逐个操作或拖入窗口。
- W5 远程截图尚未实现，后续单独设计。
- 深色模式：支持跟随系统、浅色、深色三种模式，切换会立即应用到主窗口和对话框；高对比度使用系统高对比度颜色，但个别自定义控件仍可能不完全遵循系统主题。
- 主窗口最小宽度 1000，详情面板宽度 220；低分辨率屏幕可收起详情。

## 常见问题

### 找不到对端设备

- 确认两台电脑运行的是同一构建。
- 确认两端都在应用内、保持前台，并已开启 Wi-Fi。
- 接收端先点击“等待连接”，发送端再扫描。
- 更新无线网卡驱动；部分虚拟网卡或旧驱动不支持 Wi-Fi Direct 发现。
- 如果 Windows 防火墙弹窗，请允许应用在专用网络通信。

### 接收端显示“等待中”，但发送端扫描不到

这通常表示接收端的 Wi-Fi Direct 广播已经失效，但应用仍保留着“等待中”状态。接收端不需要重启应用：

- 点击接收端的“重新等待”。按钮会停止并重新启动 PeerFinder，然后提示“等待连接已重新启动，请让对方重新扫描”。
- 从休眠恢复、解锁或 Wi-Fi/网络状态变化后，应用会自动重启等待广播。
- 连接请求被拒绝、确认超时或连接断开后，接收端也会自动重新启动广播。
- 手动点击“断开”后，接收端会立即重启等待广播，发送端会重置发现；重新扫描即可再次连接。
- 接收端在等待中且没有连接/传输时，每 2 分钟自动刷新一次广播，用于兜底 Windows 静默停止广播的情况。
- 如果“重新等待”仍无效，关闭再打开两端 Wi-Fi，或重启应用。仍然无效时，重启电脑并更新无线网卡驱动。

### 设备显示“未发现”

历史设备会保留在列表中，但只有本次扫描发现的设备才能直接连接。

- “未发现”表示对端本次不在扫描结果中。确认对端已点击“等待连接”，然后重新扫描。
- 选择标有“已发现”的设备再点击“连接选中设备”。
- 如果两台设备显示名称相同，请以本次扫描出现的那一行为准。
- 部分无线网卡每次扫描都会更换设备 ID；1.0.1 会按唯一显示名称回退匹配，并在设备列表中区分“已发现”和“未发现”。
- 发送端点击一次“扫描设备”后会持续自动重试约 15 秒；连续空结果会自动重启 Wi-Fi Direct 发现。仍失败时，确认对端已点击“等待连接”后再次扫描。

### 连接时 Windows 弹出网络或防火墙提示

- 首次运行或更换解压目录后，Windows 可能询问是否允许 `WifiDirectTransfer.App` 访问网络。
- 请选择“允许访问”，至少勾选“专用网络”。
- 如果误点拒绝：打开 **Windows 安全中心 → 防火墙和网络保护 → 允许应用通过防火墙 → 更改设置**，找到 `WifiDirectTransfer.App`，勾选“专用”并保存。
- 如果列表中没有该应用，点击“允许其他应用…”，选择发布包中的 `WifiDirectTransfer.App.exe`。
- 不建议关闭 Windows 防火墙；只需给这个应用开放专用网络权限。

### 提示协议版本不一致

两端构建不一致。1.1 起协议为 v4，不再兼容 1.0.x；请把两台电脑都更新到 1.3 或更高版本。1.3 与 1.2.x 仍可传文件，但空文件夹需要两端都是 1.3+。

### 连接后立即断开

- 检查 Wi-Fi 是否被关闭或切换网络。
- 重新扫描并连接。
- 查看日志中的握手和错误码信息。

### 接收端提示磁盘空间不足

接收端会在开始接收前检查目标磁盘剩余空间。清理接收目录所在磁盘后重试。

### 应用无法启动

- 确认压缩包已完整解压，不要直接在压缩包预览中运行 exe。
- 发布包是自包含单文件，但仍需同目录下的 WPF 原生 DLL。
- 如果 Windows SmartScreen 拦截，选择“更多信息 → 仍要运行”；发布包未签名，请用随包 SHA-256 校验文件。

### 日志和诊断

- 日志：`%LOCALAPPDATA%\WifiDirectTransfer\logs\app.log`
- 设置：`%LOCALAPPDATA%\WifiDirectTransfer\settings.json`
- 历史：`%LOCALAPPDATA%\WifiDirectTransfer\history.json`
- 诊断导出：主窗口日志栏“诊断”，会打包日志、设置、构建信息、当前速率和对端能力到 `%LOCALAPPDATA%\WifiDirectTransfer\diagnostics\*.zip`

## 从源码构建

需要 .NET 8 SDK 和 Windows 10/11。

```powershell
dotnet build WifiDirectTransfer.sln -c Release
dotnet test WifiDirectTransfer.sln -c Release --no-build
```

发布：

```powershell
.\publish.ps1
```

默认生成 `publish\artifacts\WifiDirectTransfer-1.5.1-preview-<commit>-win-x64.zip` 和对应 `.sha256` 文件。

常用参数：

```powershell
.\publish.ps1 -Label 1.5.1          # 自定义 zip 标签
.\publish.ps1 -IncludePdb           # 把 pdb 一并打包
.\publish.ps1 -SkipTests            # 跳过测试（不建议用于发布）
.\publish.ps1 -AllowDirty           # 允许未提交改动，zip 标签会带 -dirty
```

`publish.ps1` 默认要求工作区干净、应用未运行，并会执行 Release 构建和全部测试。

## 项目结构

- `src/WifiDirectTransfer.App`：WPF 桌面应用。
- `src/WifiDirectTransfer.Core`：协议、队列、文件收发、哈希、文本收件箱，无 WinRT 依赖。
- `src/WifiDirectTransfer.Windows`：PeerFinder、StreamSocket、错误映射。
- `tests/WifiDirectTransfer.Tests`：自动化测试。
